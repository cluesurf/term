
A no-crash twin whose task body is ONE statement (back divide(total, count), back read lengths/0) holds under term hold with 0/0 obligations. Why: a one-statement task is an accessor, its obligation is lifted to its callers as a precondition, and with no caller nothing owes it (test/call/hold.ts says so). Give a twin's unsafe operation a second statement (save x, divide(total, count) then back x), or a caller, and term hold refuses it.

A claim proof that matches an indexed family refines the RESULT type only. A parameter in scope whose type names the matched index (keep-top : fair a -> fair a2, while matching ok : fair-shelf (more a r)) keeps the old index, and the kernel says 'type mismatch: expected (fair a) found (fair top)'. Take such parameters AFTER the match: the claim returns a task over them (the convoy), and a separate apply claim feeds them in. Also: call a function only if it is a parameter of the claim task itself, never a parameter of a task written inside the proof (that is impure-proof, term-proof-0006).

A broken twin that removes the ONLY call of a task (aim calling guard(make yes, ...) instead of guard(may(...), ...)) is refused, but for the wrong reason: the claims whose types name that task read as 'its signature names a type the kernel cannot read (the result)' and 'a match on something that is not an enum', not as a mismatch with the law. The twin proves nothing about the law then. Keep every task the claims name called (or'ing the policy's answer with yes, twin/ownership-of-replay) so the kernel refuses with 'does not check against its claim'.

A page route's handler takes its params untyped (`take params` with no like), so a method call on it (`params/get-or-default(<id>, <>)`) compiles clean and emits `params.getOrDefault(...)`, which is not a function on the Map the host passes: every POST, PATCH and DELETE answered 500. Pass params to a task that types it (`take params / like hash / like text / like text`) and call the method there (notes/code/site.tree `id-of`). Also: a `mark sole` form (permit.tree's permit) cannot be held in a maybe or a list (check/sole.ts refuses it), so a route asks `grant-delete` inside a guarded fork and spends the permit in that same fork.

A claim's type cannot call a GENERIC task: elaborating-data.tree index-term-at says 'A task with generics is not callable here', so a law over form glyph p with escape-glyphs taking head p is refused as 'its signature names a type the kernel cannot read (the result)'. A text or number field instead reaches Lean as an axiom. Model text for a proof as payload-free cases (glyph.tree: the five HTML specials and other-point) and put each kept character back at run time beside the list (escape.tree write-pieces).
